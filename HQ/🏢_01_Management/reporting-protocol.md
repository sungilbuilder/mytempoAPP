# 보고 프로토콜 — 부서(서브에이전트) 소환 시 필수 규칙

**2026-07-30 창업자 지시로 신설.** 나중에 "누가 무슨 작업을 했는지" 검토할 수 있도록, 모든 부서 에이전트는 소환될 때마다 아래 규칙을 예외 없이 따른다.

## 1. 자기 태그

작업 시작과 종료 시 자신을 `[@에이전트이름]` 형식으로 태그한다. 예: `[@golf-mobile-developer]`. 여러 부서가 한 작업에 관여했다면 관여한 모든 에이전트를 각각 태그한다.

## 2. 진행상황 브리핑 (작업 종료 시 필수)

`HQ/📑_02_Workspace/strategy/WBS_and_daily_report.xlsx`의 `Daily_Report` 시트에 아래 컬럼으로 한 줄을 반드시 추가한다.

| 컬럼 | 내용 |
|---|---|
| Date | 오늘 날짜 |
| Department_Tag | 자신의 에이전트 이름(`[@golf-xxx]`) |
| Summary | 무엇을 했는지 3줄 이내 |
| Status | 완료 / 진행중 / 블로킹 |
| Blockers | 막힌 게 있으면 구체적으로, 없으면 "-" |
| Next_Action | 다음에 어느 부서가 무엇을 해야 하는지. **PM이 이 칸을 보고 다음 에이전트에게 지시를 내리는 용도**이므로 구체적으로 쓴다 |
| Founder_Review | 창업자(나)가 직접 봐야 하면 Y, 아니면 N |
| Founder_Note | Founder_Review가 Y일 때, 창업자가 무엇을 판단해야 하는지 한 줄 요약 |

## 3. Founder_Review = Y 로 표시해야 하는 경우

- 비용이 발생하거나 계정 개설/결제가 필요한 작업
- 저작권·상표 등 법적 리스크가 걸린 판단
- 앱 이름·브랜드·프리셋 라벨링처럼 되돌리기 어려운 네이밍/방향 결정
- 서브에이전트 신설이나 조직 구조 변경
- 애매하면 Y로 표시한다 (과소 보고보다 과다 보고가 안전)

Founder_Review = N인 항목(비용·리스크·되돌리기 어려운 결정이 없는 순수 진행상황)은 **PM 선에서 검토하고 다음 에이전트에게 바로 지시**할 수 있다. 이 프로젝트에서 "PM" 역할은 별도 에이전트가 아니라 창업자 본인이 겸하지만, 브리핑 단계에서부터 "PM이 볼 것"과 "창업자가 반드시 볼 것"을 구분해두면 나중에 검토할 때 중요한 것만 빠르게 골라볼 수 있다.

## 4. company-memory.md 연동

Founder_Review = Y인 항목은 `HQ/🏢_01_Management/company-memory.md`의 "다음 액션 후보"에도 옮겨 적는다. company-memory.md만 봐도 창업자가 놓치는 항목이 없어야 한다.

## 5. 위반 시

이 규칙을 지키지 않고 종료된 작업은 나중에 "누가 언제 무엇을 했는지" 추적이 안 되므로, `golf-strategy-lead`가 발견 시 해당 에이전트에게 재작성을 요청한다.
